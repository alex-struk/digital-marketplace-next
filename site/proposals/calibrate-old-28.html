approve by agent:product-owner (persona agent · claude claude-opus-5-5) on 2026-10-03 03:18.

Question: R-1.33 (a private opportunity note is visible only to its author and administrators) fails two tests against the old application. Is that the application's fault, the spec's, or the test's? Ruling: approve, defect-in-old. The decisive failure is the anonymous reader. In sources/old/src/back-end/lib/db/opportunity/code-with-us.ts, readOne runs processForRole at line 418, which deletes result.createdBy for any non-admin, non-author session including no session (lines 248-254). It then gates the history at lines 478-481 on session?.user.type === Admin || result.createdBy === session?.user.id. For a reader who is not signed in, both sides are undefined, so the comparison is true and the full history is returned, including the private note text, attachment name and file id. That matches the received output exactly. A signed-in non-author does not match, because their id is real; Sprint With Us uses the same gate (sprint-with-us.ts:900-904). This is a genuine access-control defect in the old application, the criterion states the intended behaviour correctly, and the test is right to assert it, so it stands as the rebuild's obligation. The second failure (signIn.public-sector-staff-other, unbound) is not a product finding. The oracle exposes no route that signs in as a second non-administrator public sector account, which is a gap in how the oracle's sign-in routes were bound. It belongs with that work and is neither test-wrong nor spec-wrong; it does not change the ruling, since only one condition per criterion is allowed and the anonymous-reader defect decides it. What would change the ruling: evidence that the old application intends opportunity history to be public, which would make this spec-wrong. The code's own comment ('If admin/owner') and its deliberate removal of createdBy for everyone else say the opposite.
